# Grill Me —— 把需求/方案问清楚

> **随包说明**:本技能随 `dsh-plugin-dev-workflow` 一起发布(包内 `skills/grill-me/`),
> 只在**已激活**的 dev-workflow 项目里出现在 DSH 技能目录中。用 `skill` 工具加载它时给出的
> "Base directory for this skill" 就是它的根目录,文中的相对路径(`references/`、`scripts/`、
> `templates/`、`assets/`)都相对那里解析。
>
> **工具名对照**(本文或许带着别的工具链的写法,在 DSH 里对应的是):`Read`/`read_file` → `read`,
> `Write`/`write_file` → `write`,`Edit` → `edit`,`Bash`/`terminal` → `pwsh`,
> `Glob`/`Grep`/`search_files` → `glob`/`grep`,`TodoWrite` → `todo_write`,
> `Task`/`delegate_task` → `subagent`,`web_extract` → `web_fetch`。
> 文中提到的脚本与模板**只有随包时才存在** —— 加载后先照 Base directory 核一眼,没有的步骤跳过,
> 或按文中原则自行实现,不要到别处去找。

一次性、有边界的追问法。目标不是"问全",而是**用最少的问题消掉最大的不确定性**。

## 什么时候用

- 需求**模糊**(关键信息缺失)→ 轻量澄清 2-3 问,问完即走
- 需求**矛盾** → 指出矛盾点,让用户在你给的选项里定夺,别自己拍
- 需求**不确定** → 记为假设列表(假设 | 如何验证 | 验证时机),不硬追问
- 需求**清晰** → 不调用,直接干活

## 三条硬规矩

1. **一个回合最多一个问题组(2-3 问)**;能合并成一次问清的绝不拆成三轮。
2. **不复述已经答过的问题** —— 用户答过的内容直接当输入,只问增量缺失项。
3. **用户说「先按这个干」「别问了」→ 立刻停止追问**,把剩下的空白写成假设列表交给下游。

## 好问题的形状

| 要问的 | 别这么问 | 这么问 |
|---|---|---|
| 范围 | "你想要什么功能?" | "第一版只做 A 还是 A+B?(B 会让工作量翻倍)" |
| 验收 | "怎么样算做完?" | "验收时你会先点哪个按钮、看到什么才算过?" |
| 约束 | "有什么限制吗?" | "必须跑在现有 Windows 机器上,还是可以上 Docker?" |

矛盾点要给**选项**:「A 与 B 不能同时成立,你选一个」比「请明确一下」有用得多。
